## 二、逐项根因与修改

### BUG-01 SecureCRT .ini 导入端口
- 根因：`int(kv.get("Port", "0"), 16) or int(kv.get("Port", "22"))`。SecureCRT 实际写的是
  `Port Number` 键；且手写/第三方导出的文件里是十进制 `22`，按十六进制读成 0x22=34。
- 修改：新增 `_parse_crt_port()`，按值形态判断——8 位十六进制 DWORD（`00000016`→22）、
  `0x` 前缀、纯十进制都正确；键名优先 `Port Number`，其次 `Port`；缺失或非法时回落到
  `PROTO_DEFAULT_PORT`（SSH/SFTP 22、Telnet 23、Rlogin 513、Serial 0）。

### BUG-02 本地 Shell 含空格路径
- 根因：`cmd = ("%s %s" % (shell, extra)).strip()`，未加引号即交给 `CreateProcessW`，
  `C:\Program Files\...` 被拆成 `C:\Program`。
- 修改：新增 `_split_cmd_args()` 把附加参数切成列表（支持双引号包裹的空格参数），
  与 shell 路径一起组成 argv，交给 `PtyConnection` 由 `quote_cmdline()`
  （即 `subprocess.list2cmdline`）统一加引号；返回给界面的说明文字同样用加引号后的命令行。

### BUG-03 删除分组误伤同前缀分组
- 根因：会话归属清理用 `startswith(folder)` 而不是按完整路径段比较。
- 修改：统一做 `base = folder.strip("/")`，判断 `f == base or f.startswith(base + "/")`；
  分组列表过滤同样按路径段处理，空分组名直接返回。

### BUG-04 保存失败静默
- 根因：`SessionStore.save` 与 `AccountStore.save` 都是 `except Exception: pass`。
- 修改：两者都改为「写 `.tmp` → `os.replace` → 返回 `True/False`」，失败时把
  `类型: 原因` 记进模块级 `LAST_SESSION_SAVE_ERROR` / `LAST_ACCOUNT_SAVE_ERROR`，
  并清理残留 `.tmp`；`SessionStore` 增加 `on_save_error` 回调与 `last_error()`。
- 界面：`MainWindow` 注册回调，失败时状态栏常驻提示 + 首次弹窗；账号管理窗口在
  添加/编辑/删除后检查 `LAST_ACCOUNT_SAVE_ERROR` 并提示。

### BUG-05 SGR 2 弱化
- 根因：`elif p == 2: self.attrs |= BOLD`。
- 修改：新增 `FAINT = 128`；`2` 置 FAINT、`22` 同时清 BOLD|FAINT、`21` 仍按取消粗体处理；
  `terminal.py` 渲染时把 FAINT（且非粗体）的前景色按 45% 混入背景色，显示为暗色。

### BUG-06 color_256 健壮性
- 根因：未校验类型与范围，`None` 抛 TypeError，负数走负索引取到色表末尾。
- 修改：`int()` 转换失败、`<0`、`>255` 一律返回 `scheme["fg"]`；`n<16` 时再校验
  `ansi` 表长度，避免色表缺项时 IndexError。

### BUG-07 串口流控
- 根因：`serial_flow` 只在会话模型里存在，`SerialConnection.start()` 从未写入 DCB。
- 修改：抽出 `apply_serial_flow(bits, flow)`，按 Win32 DCB 位定义操作 `fBits`
  （`fOutxCtsFlow` bit2、`fTXContinueOnXoff` bit7、`fOutX` bit8、`fInX` bit9、
  `fRtsControl` bit12-13、`fDtrControl` bit4-5）：
  - none：RTS 常开、不开软件流控；
  - xonxoff：OutX + InX + TXContinueOnXoff；
  - hardware：OutxCtsFlow + RTS_CONTROL_HANDSHAKE。
  统一置 DTR 使能；在 `SetCommState` 之前写入。串口打开提示里带上流控方式。

### BUG-08 代理隧道错误不上报
- 根因：`ProxyTunnel._error` 是 `pass`；`_serve` 建立上行失败后只关掉客户端。
- 修改：`ProxyTunnel.__init__` 增加 `on_error`；`_error` 调用回调并去重（同一隧道
  只报第一次）；`make_connection` 创建隧道时把 `callbacks["on_error"]` 传进去，
  从此连接建立后的代理故障也能在界面看到原因。

### BUG-09 ConPTY 句柄泄漏
- 根因：`InitializeProcThreadAttributeList` 失败、`UpdateProcThreadAttribute` 失败、
  `CreateProcessW` 失败三条分支只关了 `h_in_write`/`h_out_read`，漏 `h_in_read`/`h_out_write`。
- 修改：新增 `_close_handles(*handles)`，三条失败分支统一关闭 4 个管道句柄
  （并在 `UpdateProcThreadAttribute` 失败时补上 `DeleteProcThreadAttributeList`）。

### BUG-10 SSH-1 密码进命令行
- 事实核实：随包 `vendor/ssh1/plink.exe` 为 **Release 0.67**，实测
  `plink -pwfile <文件> -V` 返回 `plink: unknown option "-pwfile"`，即该版本**不支持**
  从文件读密码；而 PuTTY 新版本已移除 SSH-1，无法靠升级 plink 解决。
- 修改（缓解 + 明示）：
  1. 新增 `_mask_cmdline()`，返回给界面的“连接说明”里 `-pw` 后的密码显示为 `******`，
     避免密码直接出现在标签/状态栏/截图里；
  2. 首次建立 SSH-1 连接时在终端内提示：该版本只能用命令行传密码（本机进程命令行可见），
     安全要求高时改用 SSH2 + 密钥。
- 残余风险：本机管理员/同权限进程仍可通过进程命令行看到密码。这是 plink 0.67 的
  能力边界，已在使用说明与本节如实标注。

### BUG-11 DPAPI 降级为可逆 Base64
- 根因：`except` 分支返回 `"OBF:" + base64(...)`，等同明文。
- 修改：新增 `OBF2:` 格式——密钥由 `COMPUTERNAME`/`USERNAME`/`USERDOMAIN` 经 SHA256
  派生，对明文做逐字节异或后再 Base64；换机器/换用户解不出原文，副本被拷走也读不出。
  读取端兼容旧 `OBF:`（继续可解）；DPAPI 解不开或只读到弱保护格式时，设置
  `DPAPI_WARN`，连接时提示“请重新填写密码”。
- 另：`CryptProtectData` 失败不再返回空串（那是静默丢密码），改为写弱保护并留提示。

### BUG-12 防挂起乱码
- 根因：`send_anti_idle` 先 `.encode("utf-8", "replace")` 再交给 `write()`，
  而 `write()` 见 bytes 就不再按会话编码转换。
- 修改：直接把替换过 `\\n/\\r` 的字符串交给 `write()`，由 `write()` 按 `self.encoding` 编码；
  空字符串仍发 `b"\x00"`。

### BUG-13 SOCKS5 短读
- 根因：`recv(2)`/`recv(4)`/`recv(1)` 等定长单次读，未处理短读；`recv(1)[0]`
  空返回时 IndexError。
- 修改：新增 `_recv_exact(sock, n)` 循环读满，对端提前关闭抛
  `RuntimeError("代理连接被对端提前关闭")`；握手、认证、应答地址（IPv4/IPv6/域名）
  全部改用该函数，未知地址类型明确报错。

### BUG-14 变量名与 `${}` 分支
- 根因：`\w` 不含空格/短横线（部分中文列头也因此不匹配）；且 `{...}` 分支排在
  `${...}` 之前，`${name}` 变成 `$sw1`。
- 修改：正则改为 `\$\{([^{}]+)\}|\{([^{}]+)\}|%([^%]+)%`（`${}` 优先），
  键名允许中文/空格/短横线，并支持键名两侧空格容错；查不到的变量保持原样。
