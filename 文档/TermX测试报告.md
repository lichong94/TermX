## 三、缺陷详述

### BUG-01　SecureCRT .ini 导入端口按十六进制解析，十进制端口被改错（中）

- **位置**：`src/termx/sessions.py:419`（`import_crt_ini`）
- **现象**：导入 SecureCRT 会话 `.ini` 时，端口号先按十六进制解析。十进制 `22` 被当作十六进制 `0x22`，得到 **34**，导致导入后的会话连错端口。
- **复现证据**（构造含 `D:"Port"=22`、`S:"Port Number"=22` 的 ini 后调用导入）：

  ```
  [结果] 导入条数=1 解析端口=34 协议=SSH2 主机=192.168.1.10
  [判定] 端口正确(22): False
  ```

- **根因**：
  ```python
  s["port"] = int(kv.get("Port", "0"), 16) or int(kv.get("Port", "22"))
  ```
  SecureCRT ini 中端口为十进制数值，这里误用基数 16；且读取的键名 `Port` 与真实键 `Port Number` 不一致，多数情况下取不到值而回退默认，进一步掩盖了问题。
- **影响**：从 SecureCRT 批量导入的设备端口错误，连接失败或连到错误服务。
- **修复建议**：
  1. 统一按十进制 `int(..., 10)` 解析；
  2. 同时兼容 `Port Number` / `Port` 两个键名；
  3. 解析失败时回退协议默认端口（SSH 22 / Telnet 23 等），不要保留错误值。

### BUG-02　本地 Shell 路径含空格时命令行未加引号（中）

- **位置**：`src/termx/connections.py:857-863`（`create_connection` → `LocalShell`）
- **现象**：本地 Shell 命令由字符串直接拼接：`"%s %s" % (shell, extra)`。当 `shell_path` 含空格（如 `C:\Program Files\PowerShell\7\pwsh.exe`）时，未加引号，ConPTY `CreateProcessW` 按空格把路径拆成多个参数，进程启动失败或起错程序。
- **复现证据**：

  ```
  [结果] 直接拼接: C:\Program Files\PowerShell\7\pwsh.exe -NoProfile
  [结果] list2cmdline: "C:\Program Files\PowerShell\7\pwsh.exe" -NoProfile
  [判定] 空格路径未加引号: True
  ```

  对比：同文件 `quote_cmdline()`（基于 `subprocess.list2cmdline`）本可正确加引号，但本地 Shell 路径没有走它。
- **根因**：命令行构造使用手工字符串拼接，而非已有的 `quote_cmdline` 参数化拼接。
- **影响**：安装在带空格目录的 Shell（PowerShell 7、自定义终端）无法作为本地 Shell 启动。
- **修复建议**：把 `shell_path` 与 `shell_args` 拆为参数列表，统一经 `quote_cmdline([shell, *args])` 生成命令行；`shell_args` 内部再做一次参数切分（注意保留引号语义）。

### BUG-03　删除会话分组按前缀匹配，误伤同名前缀的兄弟分组（中）

- **位置**：`src/termx/sessions.py:361-368`（`remove_folder`）
- **现象**：删除分组 `核心` 时，判断会话归属用 `folder.startswith(folder)`；名为 `核心备份` 的分组同样以 `核心` 开头，其下会话被一并清空分组归属，兄弟分组被误伤。
- **复现证据**：构造两个分组 `核心`、`核心备份`，各挂一条会话，删除 `核心` 后：

  ```
  剩余会话目录=['', '']，剩余分组=['核心备份']
  ```

  `核心备份` 下的会话已被脱组（目录置空），仅空分组名残留。
- **根因**：前缀匹配未加分隔符边界，应只匹配“分组本身”或“`分组/` 子级”，不能匹配同名前缀的平级分组。
- **影响**：删除分组可能误改其它分组下会话的归属，造成会话“找不到分组”。
- **修复建议**：清空归属时判断 `f == folder or f.startswith(folder + "/")`；分组列表过滤同理（与 `rename_folder` 的边界写法保持一致）。

### BUG-04　会话库写盘失败被静默吞掉，无返回标志、无错误提示（中）

- **位置**：`src/termx/sessions.py:260-269`（`SessionStore.save`）
- **现象**：写 `sessions.json` 失败时进入 `except Exception: pass`，方法无返回值、不记录错误原因；界面层无法感知保存失败，用户以为会话已保存，实际可能丢失新增/修改。
- **对照**：`config.py` 的 `Config.save()` 已改造为返回 `bool` 并记录 `LAST_SAVE_ERROR`（交接文档“已知坑 #2”的修复），但会话库这一处未同步改造。
- **复现证据**：将保存目录置于只读位置调用 `save()`：

  ```
  [复现] 会话库写盘失败静默吞异常，无返回标志
        save() 返回值=None；对比 Config.save() 已返回 bool 并记录 LAST_SAVE_ERROR
  ```

- **根因**：异常被 `pass` 吞掉，缺少回读校验与失败提示。
- **影响**：磁盘满、目录只读、权限不足或配置文件被占用时，会话改动静默丢失。
- **修复建议**：参照 `Config.save()`：写临时文件 → `os.replace` → 回读校验；返回成功标志；失败时把原因写入可被界面读取的错误变量，并在保存会话后弹窗/状态栏提示。

### BUG-05　ANSI `ESC[2m`（Faint 弱化）被错置为粗体位（低）

- **位置**：`src/termx/ansi.py:419-420`（`_sgr`）
- **现象**：SGR 参数 `2` 标准语义为 Faint（弱化/半亮），代码却执行 `self.attrs |= BOLD`，把弱化当粗体处理。
- **复现证据**：喂入 `\x1b[2mX\x1b[0m` 后检查单元格：

  ```
  [复现] ANSI: ESC[2m 弱化被错置为粗体
        单元格 attrs=1（BOLD=1）；弱化位未定义，却置上了粗体位
  ```

- **根因**：SGR 映射表把 `2` 并入了粗体分支；终端属性位里也没有定义 Faint 位。
- **影响**：主机输出的弱化文本被显示成粗体，样式与原意相反；与 `22`（恢复正常强度）配合时状态也可能不一致。
- **修复建议**：新增 FAINT 属性位（或在渲染层把 Faint 映射为降低前景亮度）；`2` 置 FAINT，`22` 同时清除 BOLD/FAINT/ITALIC 等强度位。

### BUG-06　`color_256` 对非法索引崩溃，负数取到末尾颜色（低）

- **位置**：`src/termx/config.py:548-561`（`color_256`）
- **现象**：入参为 `None` 或非数字字符串时直接抛 `TypeError`；负数走 `ansi[n]` 负索引，取到色表最后一项而非回退前景色。
- **复现证据**：

  ```
  -1->#FFFFFF; 256->#D4D4D4; 300->#D4D4D4; None->异常:TypeError; 'x'->异常:TypeError
  ```

- **根因**：未对入参类型与取值范围做防护；负索引未拦截。
- **影响**：恶意/异常终端色号可能导致渲染异常甚至回调链上的未捕获错误。
- **修复建议**：入口先做 `isinstance(n, int)` 与范围校验；非整数或越界统一回退 `scheme["fg"]`；负数按 0 或回退处理。

### BUG-07　串口流控 `serial_flow` 配置未写入 DCB（低）

- **位置**：`src/termx/connections.py:618-640`（`SerialConnection.start`）
- **现象**：会话模型里有 `serial_flow`（none / xon-xoff / rts-cts 等）字段，但 `BuildCommDCBW` 只解析了波特率/校验/数据位/停止位，流控位未填入 DCB，配置不生效。
- **核对证据**：在 `SerialConnection.start` 源码中检索 `serial_flow`，结果为未引用：

  ```
  [判定] 串口 start() 应用 serial_flow: False
  ```

- **影响**：需要硬件流控或软件流控的串口设备，流控设置无效，可能出现收发丢字符。
- **修复建议**：按 `serial_flow` 设置 DCB 的 `fOutxCtsFlow`/`fRtsControl`（硬件）与 `fOutX`/`fInX`（软件 XON/XOFF），并在 `SetCommState` 前赋值。

### BUG-08　代理隧道上游失败时错误回调为空实现（低）

- **位置**：`src/termx/connections.py:295-296`（`ProxyTunnel._error`）
- **现象**：`_serve` 连接上游失败时调用 `self._error(str(e))`，但 `_error` 方法体只有 `pass`，代理握手/连接错误不上抛到界面回调，用户只看到会话无响应。
- **核对证据**：

  ```
  [判定] ProxyTunnel._error 空实现(错误不上报 UI): True
  ```

- **影响**：代理地址/端口错误、认证失败时缺乏明确提示，排障困难。
- **修复建议**：把错误经 `Connection._error`/回调链上报到会话状态或错误提示，与直连失败的提示口径一致。

### BUG-09　ConPTY 创建失败分支泄漏管道/伪控制台句柄（低，静态确认）

- **位置**：`src/termx/conpty.py:152-156`（属性列表初始化失败）、`189-193`（`CreateProcessW` 失败）
- **现象**：失败清理路径只关闭了部分句柄。`CreateProcessW` 失败分支关闭了 `hpcon`、`h_in_write`、`h_out_read`，但**未关闭** `h_in_read`、`h_out_write`；属性列表初始化失败分支同样漏关这两个管道句柄。
- **根因**：错误路径句柄释放清单不完整，未与成功路径对称。
- **影响**：反复启动失败的本地 Shell / SSH 会话时，句柄缓慢泄漏，长时间运行可能耗尽句柄。
- **修复建议**：失败分支统一遍历关闭四个管道句柄与 `hpcon`；可抽取 `_close_all_handles()` 在各错误出口复用。

### BUG-10　SSH-1 经 plink 时密码以 `-pw` 命令行参数传递（提示·安全加固）

- **位置**：`src/termx/connections.py:731-734`（`build_ssh1_args`）
- **现象**：密码通过 `plink.exe -pw <密码>` 进入进程命令行；同一主机上的其他用户可通过进程列表/命令行快照读到明文密码。
- **说明**：OpenSSH 路径未把密码放进命令行；本项仅影响 SSH-1（plink）通道。
- **修复建议**：优先用 plink 的 `-pwfile` 或通过标准输入/缓存凭据方式传递；至少在进程退出后不留命令行痕迹；文档中标注该通道的本机安全前提。

### BUG-11　DPAPI 不可用时降级为 `OBF:`+Base64，仅编码可逆（提示·安全加固）

- **位置**：`src/termx/sessions.py:122-129`（`_dpapi`）
- **现象**：`CryptProtectData` 抛异常时回退为 `"OBF:" + base64(utf-8)`。Base64 是可逆编码，不是加密，拿到 `accounts.json`/`sessions.json` 的人可直接解出明文。
- **说明**：本机 DPAPI 可用时走 `DPAPI:` 分支，本轮实测未触发降级路径；问题存在于异常兜底分支。
- **修复建议**：降级分支至少增加机器相关的简单混淆（避免纯 Base64 直读），并在界面提示“当前系统无法使用 DPAPI，密码以弱保护存储”；长期可考虑用户口令派生密钥。

### BUG-12　防空闲自定义字符串编码与会话编码不一致（低，静态确认）

- **位置**：`src/termx/connections.py:155`（`send_anti_idle`）配合 `write()`（136-141）
- **现象**：防空闲字符串先 `.encode("utf-8", "replace")` 成 bytes 再交给 `write()`；`write()` 收到 bytes 后不再按会话 `encoding` 编码。当会话编码为 GBK/GB18030 等非 UTF-8 时，中文防空闲串在对端显示乱码。
- **修复建议**：`send_anti_idle` 传字符串给 `write()`，由 `write()` 统一按会话编码编码；或在编码前先按会话解码/归一化。

### BUG-13　SOCKS5 响应地址按定长 `recv` 读取，未处理短读（低，静态确认）

- **位置**：`src/termx/connections.py:191-197`（`_socks5_connect`）
- **现象**：地址类型为 IPv4/域名/IPv6 时，分别 `recv(6)` / `recv(n+2)` / `recv(18)`，但 `recv` 不保证一次收满；短读会把剩余字节留在内核缓冲，污染后续终端数据流。
- **修复建议**：抽一个 `_recv_exact(sock, n)` 循环读满指定字节数，再按 atyp 解析绑定地址。

### BUG-14　批量变量替换不支持中文变量名（提示·能力限制）

- **位置**：`src/termx/sessions.py:642-647`（`expand_vars`）
- **现象**：正则 `\{(\w+)\}|\$\{(\w+)\}|%(\w+)%`，`\w+` 只匹配字母/数字/下划线，中文键名（如 `{设备}`）不被替换，原样保留。
- **复现证据**：

  ```
  输入: 设备={设备} 别名=%{name}%
  结果: 设备={设备} 别名=%sw1%
  ```

- **说明**：属设计限制而非崩溃；变量表表头用中文时占位符无法展开。
- **修复建议**：若需支持中文表头，把键名字符集放宽为中文+`\w`，并在变量表 UI 与文档中说明支持的命名规则。

## 四、静态审查中未列为缺陷、但建议关注的点

1. **大量 `except Exception: pass` 集中在 UI 回调层**（`main_window.py`、`dialogs.py`）。GUI 回调兜底可以理解，但建议至少 `traceback` 落日志，避免界面偶发无响应时无线索可查。
2. **会话导入跨机器 DPAPI 不可解**：`import_json`/`import_crt_ini` 保留的 `password_enc` 在另一台机器/用户下无法 DPAPI 解开；导入后应提示用户重填密码，或导入时改为明文暂存并在目标机重新加密。
3. **`_resolved_dir` 缓存与运行目录切换**：切换数据目录后，已实例化的 `Config`/`SessionStore` 需调用 `rebind`/重建，否则仍指向旧文件；建议在目录切换流程里统一刷新所有已持有存储实例。
4. **Zmodem 已知边界**：`zmodem.py` 文档已自陈多子包流式、个别 lrzsz 版本 CRC 约定为容忍策略，本轮未与真实 `lrzsz` 对端联调，建议后续补真机收发用例。
