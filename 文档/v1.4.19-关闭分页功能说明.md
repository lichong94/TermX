# v1.4.19 关闭分页（批量下发）功能说明

> 版本：TermX v1.4.19（2026-11-19）
> 位置：批量下发窗口 → ③ 下发参数 → **关闭分页**
> 目的：批量跑长输出命令（`display current-configuration`、`show running-config` 等）时，设备分屏会卡在 `---- More ----`，导致后续命令全乱。本功能在每台设备登录确认后自动先关分页。

## 1. 界面

③ 下发参数区新增一行：

```
关闭分页:  [ 下拉框：华为 / 华三 / 自建厂商 ... /（不执行） ]   [管理厂商…]   登录后自动执行：<命令>
```

- 下拉框第一项固定为 `（不执行）`，选它等于关闭该功能。
- 选中的厂商写在 `settings.json` 的 `paging_active`，下次打开窗口自动恢复。
- 「管理厂商…」打开管理窗口：可**添加 / 编辑 / 删除 / 恢复内置厂商**，双击行等于编辑。

## 2. 内置厂商命令（均已核对厂商官方文档）

| 厂商 | 命令 | 视图 | 生效范围 | 出处 |
|---|---|---|---|---|
| 华为（VRP） | `screen-length 0 temporary` | 用户视图 | 仅当前会话，退出不保存 | 华为命令参考 EDOC1100325908 / EDOC1100468209 |
| 华三（Comware） | `screen-length disable` | 用户视图 | 仅本次登录，重登录恢复 | H3C「01-CLI命令」1.1.14 screen-length disable |

两条都是**临时**设置，不写配置、不影响其他登录用户，`undo` 即可恢复。

其它厂商（思科 `terminal length 0`、锐捷等）未内置，需要时在「管理厂商…」里自行添加。

## 3. 执行时序（每台设备）

```
建立连接 → 等 is_connected
        → 等自动登录应答线程结束（AutoLoginRunner.busy() == False）
        → 等命令行提示符出现（0.8 s 内没等到 → 补发一个回车唤起提示符，再等 6 s）
        → 下发 [关闭分页] 命令 → 等提示符回显
        → 才开始执行用户填写的批量命令（按变量行展开）
```

- 关闭分页**每台设备只发一次**，不随变量行重复。
- 命令执行前先确认登录，避免把命令误发到 `Password:` 提示上（那会被当作密码输入）。
- 关闭分页**失败不阻断**：结果列表里单独记一条 `[关闭分页·华为] screen-length 0 temporary`，状态标「失败」，后面用户的命令照常执行。

## 4. 结果列表

关闭分页作为一条结果出现在 Treeview 最前面，命令列显示为：

```
[关闭分页·华为] screen-length 0 temporary
```

进度条总数相应每台设备 +1（`BatchDispatcher.total`）。

## 5. 持久化

均在运行目录 `settings.json`：

| 键 | 类型 | 说明 |
|---|---|---|
| `paging_vendors` | object | 自建/覆盖厂商 `{"名称": "命令"}` |
| `paging_deleted` | array | 已删除的内置厂商名（黑名单，可「恢复内置厂商」找回） |
| `paging_active` | string | 上次选中的厂商，空 = 不执行 |

删除内置厂商只是加黑名单，删掉自建厂商则从 `paging_vendors` 移除；同名自建可覆盖内置。
